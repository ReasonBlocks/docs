This is the default integration surface for ReasonBlocks: route agent traffic through your
**hosted gateway**, capture workflow traces, and serve a cheaper task-specific model with frontier-model fallback through
the same URL.

For the step-by-step flow, start with [Quickstart](/quickstart). The gateway base URL and the
two-line shim are both required; the only choice left is whether `install()` alone covers the
process or each job needs `run()` — see [Integrating your agent](/client-integration).

## Gateway URL

Copy your tenant gateway URL from [app.reasonblocks.com](https://app.reasonblocks.com)
Quickstart:

```bash
export ANTHROPIC_BASE_URL="https://gateway.<your-tenant>.reasonblocks.com"
```

| Item | Detail |
| --- | --- |
| Protocol | Anthropic Messages (`POST /v1/messages`) is the primary path. OpenAI and other LLM APIs are supported for capture. See [Endpoint compatibility](/endpoint-compatibility). |
| API key | Your existing `ANTHROPIC_API_KEY`; passes through upstream, **never stored** |
| Agent code | Unchanged except `ANTHROPIC_BASE_URL` and the two-line shim |
| Failure mode | Byte-transparent, fail-open: if capture breaks, traffic still flows |

## Agent environment variables

### `ANTHROPIC_BASE_URL`

**Required** for capture and serving.

<ParamField path="ANTHROPIC_BASE_URL" type="string" required>
  Hosted gateway URL from the dashboard. Must be set **before** the agent process starts.
  After training, keep the same URL. Go live with your trained model in the dashboard (your
  model primary; frontier backup on edge cases).
</ParamField>

```bash
export ANTHROPIC_BASE_URL="https://gateway.<your-tenant>.reasonblocks.com"
export ANTHROPIC_API_KEY="sk-ant-..."   # unchanged; passthrough only
```

### `ANTHROPIC_API_KEY`

Your Anthropic API key. ReasonBlocks forwards it to upstream on each request. It is not
persisted in capture storage.

### `RBTRACE_DISABLE`

**Escape hatch**, not a supported mode.

<ParamField path="RBTRACE_DISABLE" type="string" default="unset">
  Set to `1` to disable the client shim without removing code. Capture continues through the
  gateway, but for as long as it is set the agent degrades to gateway-only passive inference and
  its runs are largely not minable. See
  [Integrating your agent — Kill switches](/client-integration#kill-switches).
</ParamField>

## Client shim (required)

Install in the **agent** environment alongside the gateway base URL. It is required for every
client whose HTTP transport it can patch — `httpx`, `httpx2`, `aiohttp` and `botocore`, which
between them carry the Anthropic, OpenAI, google-genai and boto3 Python SDKs and the frameworks
built on them. Without it, run boundaries are inferred rather than proven and most runs never
become minable:

```bash
pip install rbtrace   # when published to PyPI
```

<ParamField path="rbtrace.client.install()" type="function">
  Call once at process startup. Stamps `X-RB-Run` and `X-RB-Seq` on outbound LLM HTTP
  requests. Patches every transport it finds importable: `httpx` and `httpx2` (the Anthropic
  and OpenAI Python SDKs), `aiohttp` (google-genai's async client) and `botocore` (boto3 —
  which sends through `urllib3`, so it gets botocore's `before-send` event hook instead of a
  patched client; the hook fires after SigV4 signing, so the headers stay outside the
  signature). Returns `False` if it patched nothing, and warns by name when google-genai +
  `aiohttp` or boto3 are installed but unpatched. Does not replace the gateway;
  `ANTHROPIC_BASE_URL` must still point at ReasonBlocks.
</ParamField>

<ParamField path="rbtrace.client.install_botocore(session=None)" type="function">
  Only needed for a boto3 client or session built **before** `install()` ran — `install()`
  registers botocore's hook for every session built after it, and cannot reach one that
  already exists. Accepts a boto3 client, a boto3 `Session`, a botocore `Session`, an event
  emitter, or nothing for boto3's default session if one has been created. Returns whether it
  registered; repeat calls are no-ops.
</ParamField>

<ParamField path="rbtrace.client.installed_transports()" type="function">
  The transports actually patched, as a tuple. Worth asserting at start-up: an unpatched
  transport looks exactly like a working one until the runs turn out not to be minable.
</ParamField>

<ParamField path="rbtrace.client.run()" type="context manager">
  One fresh run id per `with` block. Needed whenever one process handles more than one logical
  job — batch loops, worker pools, threaded workers — so distinct jobs do not merge into one
  trace. A single-job process needs `install()` only.
</ParamField>

```python
import rbtrace.client

rbtrace.client.install()

for task in tasks:
    with rbtrace.client.run():
        run_agent(task)
```

Full decision guide, and the clients the shim cannot reach:
[Integrating your agent](/client-integration).

## What the gateway captures

Each Anthropic Messages request/response pair that transits the gateway is written to hosted
storage. ReasonBlocks reconstructs runs server-side and labels them:

| Label | Meaning |
| --- | --- |
| **golden** | Proven complete run; eligible for distillation (`supports_universal_claims: true`) |
| **not** | Incomplete or violated; excluded from mining |

Review counts in the dashboard. The shim is what makes **golden** the common case rather than
the exception; scoping `run()` per job is what keeps it that way in multi-job processes.

For OpenAI Chat Completions, Responses API, Gemini, and other paths, see
[Endpoint compatibility](/endpoint-compatibility).

## Training and trained model serving (hosted)

Training and serving your trained model run on ReasonBlocks infrastructure under your tenant. Start
jobs and read reports in the dashboard; see [Quickstart](/quickstart) steps 4–6.

After training, serving uses the same `ANTHROPIC_BASE_URL` with a **flat** transcript contract
(`render_flat`). Multi-turn serving of a flat-trained model silently underperforms; see the
Warning on [Quickstart](/quickstart).

| Who answers | Behavior |
| --- | --- |
| **Your trained model (primary)** | Task-specific model trained on your workflow handles the request |
| **Frontier backup** | When coverage runs out or the step fails, the gateway uses your frontier model |
| **Edge-case loop** | Backup episodes are captured and feed the next training cycle |

## Self-hosted gateway (advanced)

If you run `rbtrace proxy` on your own infrastructure instead of the hosted gateway, agent
integration is the same env var pattern with your host URL. Operator endpoints, Docker, and
local distillation CLI are documented under
[Deployment — Advanced: self-hosting](/deployment#advanced-self-hosting-the-gateway).

### Upstream routing

One gateway serves every provider. Which upstream a request goes to is decided by the leading
path segments — the **provider prefix** — which the gateway then strips before forwarding.

<ParamField path="AGENTRECON_UPSTREAM_BASE" type="string" default="https://api.anthropic.com">
  The **no-prefix** upstream: where a request goes when its path matches no prefix. The
  client's path is appended verbatim. This is the original single-upstream behaviour and is
  unchanged — a deployment that sets nothing else sees no difference. `AGENTRECON_PROVIDER`
  (default `anthropic`) is the provider label written on those rows.
</ParamField>

<ParamField path="AGENTRECON_UPSTREAMS" type="JSON object" default="built-in table">
  A JSON object mapping prefix to upstream base URL, merged **over** the built-in defaults
  (`/anthropic`, `/openai`, `/gemini`, `/bedrock/<region>`, `/fireworks`). A prefix already in
  the defaults is overridden; a prefix mapped to `null` is removed. Prefixed rows take their
  provider label from the route, not from `AGENTRECON_PROVIDER`.

  A prefix segment written as `<name>` is a wildcard whose value is substituted into the
  upstream — that is how one `/bedrock/<region>` route serves every AWS region. Matching is
  whole-segment and longest-prefix-first, so `/openaifoo` is not `/openai`.

  A malformed value raises at startup with the variable named, rather than silently routing a
  tenant's traffic — and its API key — to the wrong host.
</ParamField>

```bash
# add an internal vLLM host, and take /openai off this gateway entirely
export AGENTRECON_UPSTREAMS='{"/vllm": "http://vllm.internal:8000", "/openai": null}'
```

Removing a prefix matters when the no-prefix upstream is itself a Bedrock runtime, whose own
`/anthropic/v1/messages` and `/openai/v1/*` routes would otherwise be claimed by the
`/anthropic` and `/openai` prefixes.

`python -m rbtrace.proxy --upstream <url>` sets the no-prefix upstream only; it does not touch
the prefix table.

### Operator endpoints

Served at the gateway **root** only — under a provider prefix they are ordinary client paths
and get forwarded upstream.

| Endpoint | Purpose |
| --- | --- |
| `GET /__rbtrace/stats` | Queue depth, exchange counts, health |
| `POST /__rbtrace/flush` | Flush batched writes before DB backup |
| `GET /__rbtrace/routes` | The effective prefix → upstream table, defaults merged with `AGENTRECON_UPSTREAMS` |

Self-hosted trained model serving after local distill uses `RBTRACE_DISTILL_DIR`; see
[Quickstart — Advanced](/quickstart#advanced-run-the-pipeline-locally) and trace-reconstructor
operator docs for gateway serve config.
