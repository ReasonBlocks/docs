title: "Quickstart"
description: "Connect a source with one server key and verify recording automatically."

Connect your existing application in **Data**. Keep your provider client and credentials.
No sandbox is needed to record calls, and connecting does not start training.

## 1. Create a source and server key

In **Data**, create a source and open **Manage connection**. Choose your provider
and **Generate server key**. The key has **Capture** and **Inference** permissions
for this source. Leave expiration blank for a persistent key, or choose an expiration.
Store the one-time secret as `REASONBLOCKS_API_KEY` on your server.

An existing `rb_live_` key works when it has Capture permission and access to the
source. Older keys may have Inference permission only; check **API Keys**.
Legacy `rbcap_` source keys also remain supported. New source keys have no scheduled
expiration, and rotation allows a 24-hour overlap, bounded by the old key's expiry.
Existing keys retain their original expiration until you replace them.

## 2. Keep one source URL and key

Copy the setup code from **Manage connection**. Your existing Anthropic or OpenAI
SDK connects directly; no ReasonBlocks helper installation is required. The same
source URL and ReasonBlocks key are used for recording and supported serving after
you approve a release. Keep your provider credential and original model ID.

```python
import os
from anthropic import Anthropic

SOURCE_URL = "https://api.reasonblocks.com/capture/SOURCE_ID/anthropic"

def client_for_task(task_id):
    return Anthropic(
        base_url=SOURCE_URL,
        default_headers={
            "x-reasonblocks-key": os.environ["REASONBLOCKS_API_KEY"],
            "x-rb-run": task_id,
        },
        max_retries=0,
    )

client = client_for_task("your-unique-task-id")
# Pass client to your existing agent, including its tool loop.
```

Keep `ANTHROPIC_API_KEY` in its usual environment variable. For OpenAI, use
`OpenAI` and the source URL ending in `/openai/v1`. Use a unique `x-rb-run` for
each complete task, including all model calls and tool execution. If you reuse a
long-lived SDK client, pass the task's `x-rb-run` through `extra_headers` on each
call instead of setting it as a client default.

For native Bedrock, install `rbtrace==1.3.0` once and instrument your existing
boto3 client. Keep its IAM credential chain:

```python
from rbtrace import Connection

rb = Connection(source_id="SOURCE_ID")
rb.instrument_bedrock(existing_boto3_client, serving=True)
# Run each complete task inside with rb.run("your-unique-task-id").
```

No Anthropic API key is required for native Bedrock calls. See
[Integrating your agent](/client-integration) for native Bedrock behavior and
[Set up with your coding agent](/agent-setup) for existing CLI integrations.

## 3. Verify the connection automatically

Run your application and keep **Manage connection** open. Its status refreshes
without inspecting response headers. It shows recorded requests, training examples,
training exclusions, failures, recent activity and connection-key expiration warnings.

A request can be recorded while excluded from training. Open the reason in the
connection status before changing your application. If you use the optional
Connection helper, `rb.status()` reads server status and `rb.diagnostics()` reports
local SDK delivery information.

Normal provider fees apply to model calls. Status checks do not generate a model response.

## 4. Prepare training when ready

Training needs representative tasks, a resettable test copy of your tools and
data, and a way to evaluate completed tasks. Follow
[Train your complete agent](/full-agent-training) to prepare a plan and review
the budget before authorizing paid work. Enable a supported release in the
dashboard when ready; your source URL, ReasonBlocks key and existing client stay
the same. Continue with
[Work with your coding agent](/agent-workflow) to review readiness and rollout.
