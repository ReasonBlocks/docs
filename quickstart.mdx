---
title: "Quickstart"
description: "From your first captured run to a promoted small model."
---

## 1. Run the capture proxy

```bash
git clone <trace-reconstructor repo> && cd trace-reconstructor
pip install -e .

python -m rbtrace.proxy --db data/captures/capture.duckdb --note production
# or: docker compose up -d
```

## 2. Point your agent at it

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:8787
python your_agent.py     # unchanged otherwise; your API key passes through, never stored
```

Optionally stamp exact run boundaries (recommended for production accuracy):

```python
import rbtrace.client
rbtrace.client.install()

with rbtrace.client.run():       # one run id per job
    agent.handle(task)
```

## 3. Check what you've collected

```bash
python -m rbtrace inspect data/captures/capture.duckdb
python -m rbtrace trace data/captures/capture.duckdb --format rb_trace_v1 -o traces.jsonl
```

The trace command reports how many runs support universal claims — those are the
runs the distillation pipeline is allowed to learn from.

## 4. Distill

```bash
export FIREWORKS_API_KEY=fw_...
export FIREWORKS_ACCOUNT_ID=accounts/your-account

# Free dry run: builds the dataset, touches no paid API
python -m rbtrace distill data/captures/capture.duckdb --tenant acme --dry-run

# The real thing
python -m rbtrace distill data/captures/capture.duckdb --tenant acme
```

The pipeline runs `dataset → sft_v1 → eval_v1 → rft → sft_v2 → eval_v2 → report`,
checkpointing each stage under `distill-acme/`. Interrupted runs resume; if the
capture doesn't yet hold enough complete runs it exits cleanly with "not ready", so
you can run it on a schedule and let it fire when collection catches up.

## 5. Read the report

`distill-acme/REPORT.md` gives you the held-out shadow-fidelity table (tuned vs
untrained base, with the repair-turn subset broken out), the promotion verdict, and
the serving contract. If a model was promoted, it is live on your Fireworks account
under `rb-<tenant>-slm-v2`.

<Warning>
Serve the model **exactly as trained**: the transcript flattened into one role-tagged
user turn with the training instruction appended (`rbtrace.distill.dataset.render_flat`).
A flat-trained model served multi-turn silently underperforms.
</Warning>

## Tuning the pipeline

Pass `--config distill.json` to override any knob — holdout fraction, example caps,
base model, LoRA rank, spend ceiling, promotion margin. See `distill.example.json`
in the repo for the full set with defaults.
