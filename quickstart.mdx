title: "Quickstart"
description: "Copy your gateway URL from the dashboard, set one environment variable, and let ReasonBlocks capture, train a cheaper task-specific model, and serve it with frontier-model fallback."
---

ReasonBlocks hosts the capture gateway, storage, trace reconstruction, distillation pipeline,
and relegation serving. Your integration starts in the dashboard, not on a local server.

## 1. Get your gateway URL

Sign in to [app.reasonblocks.com](https://app.reasonblocks.com) and open **Quickstart**.

Copy your tenant gateway URL. It looks like:

```bash
export ANTHROPIC_BASE_URL="https://gateway.<your-tenant>.reasonblocks.com"
```

Use the exact URL shown in the dashboard. Do not substitute `localhost` unless you are
[self-hosting the gateway](/deployment#advanced-self-hosting-the-gateway).

## 2. Set the environment variable and run your agent

Set `ANTHROPIC_BASE_URL` before starting your agent. Use your existing Anthropic API key as
you always have. ReasonBlocks passes it through to upstream and **never stores it**.

```bash
export ANTHROPIC_BASE_URL="https://gateway.<your-tenant>.reasonblocks.com"
export ANTHROPIC_API_KEY="sk-ant-..."   # your existing key; unchanged
python your_agent.py                     # no other code changes required
```

Your agent speaks the Anthropic Messages protocol to ReasonBlocks when using
`ANTHROPIC_BASE_URL`. OpenAI and other providers use the same gateway with different base URL
env vars. See [Endpoint compatibility](/endpoint-compatibility). The gateway is
byte-transparent and fail-open: if capture ever breaks, your traffic still flows.

For proven run boundaries (recommended before distillation), see [Integrating your agent](/client-integration).
**Tier B or C** adds a small client shim; the gateway stays hosted.

## 3. Confirm capture in the dashboard

After a few agent runs, open the dashboard **Captures** view (or the Quickstart progress panel).

You should see:

- Exchange count growing as your agent runs
- Runs labeled **golden** (eligible for training) or **not** (incomplete or violated, excluded from mining)

You do not need local DuckDB files or `rbtrace inspect` for the default path. ReasonBlocks
reconstructs traces on hosted storage automatically.

## 4. Start training (hosted, opt-in)

Training is **opt-in** and **tenant-scoped**. ReasonBlocks does not train on your traffic
until you start a job from the dashboard (or an approved automation hook).

In the dashboard:

1. Open **Distillation** (or **Train** on Quickstart).
2. Confirm you have enough **golden** runs for this workflow. If not, the UI shows "not ready"
   and you can keep capturing until the threshold is met.
3. Start a run. ReasonBlocks mines policies from your golden traces and fine-tunes a **cheaper
   task-specific model** on your workflow.

Training runs on ReasonBlocks infrastructure under your tenant. You configure spend limits and
schedules in the dashboard, not by SSHing into a capture host.

## 5. Read the training report

When a job finishes, open the **Report** in the dashboard.

The report includes:

- Training summary and model identifier
- Serving contract (flat transcript format)
- Whether relegation routing is ready to enable

## 6. Enable relegation serving (same env var)

Keep `ANTHROPIC_BASE_URL` pointed at the same gateway URL. Enable serving in the dashboard
when the report says the model is ready.

**How routing works:**

1. **Cheaper model first.** Most steps go to your task-specific model trained on this workflow.
2. **Frontier fallback.** When the cheaper model lacks coverage or fails a step, ReasonBlocks
   routes that request to your frontier model. Your agent still sees one API; the gateway
   handles the switch.
3. **Continuous improvement.** Fallback episodes are captured as edge cases and feed the next
   training cycle so coverage expands over time.

The agent still speaks Anthropic Messages. ReasonBlocks serves the flat transcript contract
from the training report.

<Warning>
Serve the model **exactly as trained**: the transcript flattened into one role-tagged user
turn with the training instruction appended (`render_flat`). A flat-trained model served
multi-turn silently underperforms.
</Warning>

## Optional: client shim (Tier B / C)

If you need high **golden** yield (batch workers, multi-job processes), install the client
shim in your agent environment:

```bash
pip install rbtrace   # when published to PyPI
```

Then follow [Integrating your agent](/client-integration) for `rbtrace.client.install()` and
optional `with rbtrace.client.run():` per job. The gateway URL and capture path are unchanged.

## Advanced: run the pipeline locally

Use this only when you operate the gateway and storage yourself. See
[Deployment](/deployment#advanced-self-hosting-the-gateway).

```bash
pip install rbtrace   # when published; or install from a release artifact

python -m rbtrace inspect /path/to/capture.duckdb
python -m rbtrace trace /path/to/capture.duckdb --format rb_trace_v1 -o traces.jsonl

export FIREWORKS_API_KEY=fw_...
export FIREWORKS_ACCOUNT_ID=accounts/your-account
python -m rbtrace distill /path/to/capture.duckdb --tenant acme --dry-run
python -m rbtrace distill /path/to/capture.duckdb --tenant acme
```

Self-hosted relegation serving after a local training run (implementation uses env vars from
the distill output directory):

```bash
export RBTRACE_DISTILL_DIR=./distill-acme
# Enable relegation routing on the gateway host (see trace-reconstructor operator docs)
```

Pass `--config distill.json` to override holdout fraction, example caps, base model, LoRA rank,
and spend ceiling. Defaults are in `distill.example.json` on the
[`trace-reconstructor`](https://github.com/ReasonBlocks/trace-reconstructor) repo.
