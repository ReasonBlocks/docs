---
title: "What is ReasonBlocks?"
description: "Drop in an API proxy, collect your agent's traces, and come out with a fine-tuned small model that replaces the big one — automatically, and only if it proves itself on your own held-out workflow."
---

ReasonBlocks distills the expensive frontier model behind your production agent into a
small model trained on your agent's own captured behavior. Integration is one
environment variable; everything downstream — trace reconstruction, dataset mining,
training, evaluation, promotion — is automated.

## The problem

Production agents run the biggest model on every step because nothing smaller can be
trusted with the workflow. But most of what a mature agent does is deeply repetitive:
the same tools, the same verify scripts, the same repair moves against the same gate
failures. You are paying frontier prices — often hundreds or thousands of dollars per run —
for behavior a 32B model can learn from a few dozen recorded sessions.

## How it works

<Steps>
  <Step title="Point your agent at the proxy">
    Set `ANTHROPIC_BASE_URL` to the ReasonBlocks capture proxy. Your API key passes
    through untouched (it is never stored); every exchange is captured durably. The
    proxy is byte-transparent and fail-open: if capture ever breaks, your traffic
    doesn't.
  </Step>
  <Step title="Traces reconstruct themselves">
    The reconstruction layer turns raw traffic into verified runs — ordered steps,
    tool calls paired to their results, injected corrections identified structurally.
    Only runs proven to be observed *whole* are eligible for training.
  </Step>
  <Step title="The distillation pipeline runs">
    `rbtrace distill` mines (state → action) pairs from complete runs, fine-tunes a
    32B student on them, evaluates it against held-out sessions, runs one round of
    verifier-gated rejection sampling, retrains, and re-evaluates.
  </Step>
  <Step title="A model is promoted — or honestly isn't">
    The student is promoted only when it beats the untrained base model on your own
    held-out states by a margin. The report names the model and the serving contract,
    or tells you exactly why nothing shipped.
  </Step>
</Steps>

## What makes it trustworthy

- **Completeness is proven, not assumed.** A run with a hole in it is never mined;
  the reconstruction layer proves each run was captured whole before the pipeline
  may quantify over it.
- **A deterministic step verifier guards every sampled action** — known tool, real
  helper script, well-formed arguments — with the valid vocabulary mined from your
  own traces rather than configured by hand.
- **Whole-action selection only.** Rejection sampling keeps or drops complete
  actions; nothing selects on sub-action criteria, which measurably mines verifier
  false positives.
- **Spend ceilings everywhere.** Training jobs are cancelled the moment the
  provider's own cost estimate crosses your cap; GPU deployments tear down in
  `finally`.
