## Hosted (default)

ReasonBlocks operates the capture gateway, durable storage, trace reconstruction,
distillation pipeline, and trained model serving for your tenant. Your trained model is served
to you under license through the hosted gateway — you get inference against your model, not
the weights to run or redistribute elsewhere.

**What ReasonBlocks runs**

- Hosted gateway at a tenant-specific URL (copy from [app.reasonblocks.com](https://app.reasonblocks.com) Quickstart)
- Capture storage and trace reconstruction
- Distillation jobs, training reports, and serving your trained model (frontier as backup)

**What you configure**

| Item | Where |
| --- | --- |
| Gateway URL | [app.reasonblocks.com](https://app.reasonblocks.com) → Quickstart → copy into `ANTHROPIC_BASE_URL` |
| Anthropic API key | Your agent environment (passthrough; never stored by ReasonBlocks) |
| Integration | [Integrating your agent](/client-integration): gateway base URL **and** the two-line `rbtrace` shim — both required |
| Distillation | Opt-in, tenant-scoped |
| Trained model serving | Your model primary, frontier backup on edge cases |

Your agent process needs the gateway URL via `ANTHROPIC_BASE_URL`, your existing API key, and
the two-line client shim. No DuckDB files, no locally run gateway, and no SSH access required
for the default path.

Anthropic Messages is the primary path for training and for trained model serving. OpenAI Chat
Completions, Responses API, Gemini, and other routes are supported for capture via the same
gateway URL with the correct client env var. See [Endpoint compatibility](/endpoint-compatibility).

See the [Quickstart](/quickstart) for the end-to-end hosted flow.

### Security and privacy

- Anthropic API keys pass through the gateway to upstream and are **not stored** by ReasonBlocks.
- Capture data and distillation artifacts stay in your tenant scope on ReasonBlocks infrastructure.
- The agent shim only stamps two HTTP headers (`X-RB-Run`, `X-RB-Seq`) on recognised LLM API
  paths; it reads no bodies, sends nothing of its own, and does not replace the hosted gateway.

## Integration

Where the gateway runs is separate from how you label runs in your agent process. Both pieces of
the client integration are required: point the SDK's base URL at the gateway, and install the
shim. See [Integrating your agent](/client-integration) for the one remaining choice —
`install()` alone, or `install()` plus `with rbtrace.client.run():` per job — and for the clients
whose transport the shim cannot reach.
